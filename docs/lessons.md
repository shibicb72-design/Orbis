# Lessons (Orbis)

- Debug keystore is committed and shared so CI and local APKs update in place. Never use `~/.android/debug.keystore` as the app signing source of truth.
- Updates come from Google Play. Do not add an in-app GitHub release check. `retireGithubUpdateChecker` deletes `update_prefs` and cancels the WorkManager job `com.shibi.orbis.update.check` left by older builds.
- UI must not call GeckoView types; keep a thin `BrowserEngine` boundary.
- uBlock Origin is AMO-onboarded, not APK-bundled, for v1.
- Error / debug log UI lives only under Settings.
- GeckoView and `browser-engine-gecko` must stay on a matching major/channel pair from maven.mozilla.org.
- `GeckoSessionSettings.useTrackingProtection` defaults to false: set it true on every session or ETP does nothing there; build `ContentBlocking.Settings` via its Builder, not just `setEnhancedTrackingProtectionLevel`.
- `WebExtensionController.install()` hangs forever (no error) if no `PromptDelegate` is set or `onInstallPromptRequest` returns null; set the delegate at runtime creation and always return a result.
- `Application.onCreate` also runs in Gecko child processes (`:tab`, `:gpu`); return early when `Application.getProcessName() != packageName` so no runtime or container is created there.
- The browser session must outlive the composition: own it in `AppContainer` (via `TabManager`), never `close()` it in a composable `onDispose`, or opening Settings destroys the page.
- Every `PromptDelegate` callback returns a `GeckoResult<PromptResponse>` and a `BasePrompt` can also be dismissed by Gecko itself (`setDelegate(...).onPromptDismiss`, `isComplete()`): complete each result exactly once (a once-only wrapper), and complete all pending ones on session close and on crash/kill, or the page hangs.
- `ButtonPrompt` in this GeckoView carries only `message` and POSITIVE/NEGATIVE; there are no button labels to show. `GeckoSession.SessionState` round-trips through `toString()`/`fromString()` (that string is what the tab list persists; `fromString` can fail, so keep a url fallback).
- `WebResponse.body` (from `ContentDelegate.onExternalResponse`) is a live `InputStream`: every response must end in a read-to-end or a close, even when nobody wants it (no host, background tab, user says no).
- One `GeckoView` shows one session: release the attached one (`releaseSession()`) before `setSession(other)`, and make the swap idempotent (Compose `update` re-runs); a popup child from `onNewSession` is handed to Gecko unopened, so never call `open` on it.
- Popup gating holds because Gecko calls `NavigationDelegate.onLoadRequest` (via `LoadURIDelegate.load` in `GeckoViewNavigation`) before `onNewSession` for every window-open path, so the user-gesture and http(s) check in `onLoadRequest` is the primary gate; `onNewSession` re-checks the scheme only as defense in depth.
- `FilePrompt.confirm` only maps a `content://` Uri to a filesystem path (external-storage documents or the `_data` column), which needs storage permission and fails for most providers; an unresolved file makes `FilePickerDelegate` return cancel, so the page silently sees nothing chosen. Copy picks into app-private cache and confirm with `file://` Uris. Do not delete the copies after confirm: Gecko reads the path at form-submit time.
- `GeckoViewPermission.promptPermission` stores every geolocation answer with EXPIRE_NEVER, after which `onContentPermissionRequest` never fires again for that site, and an Android-level denial becomes a permanent site deny. Keep our own decision store as the only authority and reset Gecko's copies with `StorageController.setPermission(entry, VALUE_PROMPT)`, including at runtime start for denies left by older builds.
- Gecko's Android request for camera/mic goes to `getMostRecentWindow`, not the requesting tab, and comes before the site prompt; its result is ignored (no permission means no devices enumerate, so the request is denied). Route Android requests through an app-level broker, never a per-tab queue. Geolocation is the other way round: site prompt first, then ACCESS_FINE_LOCATION only, and with targetSdk 31+ FINE must be requested together with COARSE.
- Camera capture for `<input type=file capture>`: `FilePrompt.capture` is only an int (NONE/ANY/USER/ENVIRONMENT) and `mimeTypes` are the raw accept tokens, so decide the route ourselves (`filePickRoute`). Because the manifest declares CAMERA, `ACTION_IMAGE_CAPTURE` throws `SecurityException` until the permission is granted: ask through the broker first and create nothing before the answer. The camera writes into `cacheDir/camera_capture/` (its own FileProvider path, never `uploads/`), and the photo is then copied through `UploadCache` like any pick, so the camera app's Uri grant never touches what Gecko reads. Delete the temp only when the prompt ends, not before the copy finished.
- Judge "Android has blocked the dialog" only after a system request returns (denied, no rationale, asked before). A pre-check mistakes an expired "Only this time" grant for a block.
- A download's `WebResponse.body` lives in the app process with Gecko, so a foreground service protects it through backgrounding and swipe from Recents but not a hard kill. A foreground service does not stop CPU sleep: hold a partial wake lock with a timeout.
- Android 11 package visibility: `resolveActivity` returns null for schemes this app cannot see, and a `<queries>` row with `host="*"` does not match hostless schemes such as `magnet:`. Do not treat that null as "no app", and do not re-add `QUERY_ALL_PACKAGES`. Call `startActivity` (`ACTION_VIEW`, `CATEGORY_BROWSABLE`) and show the message only on `ActivityNotFoundException`. `intent:` links are `Intent.parseUri(URI_INTENT_SCHEME)` with component, selector, flags and extras stripped, then `browser_fallback_url`, then `market://details?id=`.
- History visits: in GeckoView 159 `StateTracker` sends PageStart at STATE_START, before the commit's LocationChange, and PageStop only when the document finishes; same-document navigations send LocationChange alone. `GeckoViewNavigation.onLocationChange` does not look at the error-page flag, so treat any location after `onLoadError` as not a visit until the next PageStart. A titleless page may never get `onTitleChange`, so `SessionState.title` can be the previous page's.
- Foreground service crash traps: every start through `startForegroundService` must reach `startForeground` even with an empty queue, nobody calls `stopService` from outside, stop with `stopSelfResult(startId)` so a newer start wins, and on API 35+ `onTimeout` must stop the service.
